# 2단계 — Todo 리스트 리팩토링: useEffect와 파생값

> 1단계의 원칙이 규모가 커지면 어떻게 무너지는지 본다.
> 동작은 전부 한다 — 하지만 상태가 왜 이렇게 많은지 아무도 설명하지 못한다.

## 왜 이 과제를 하는가

- 이 컴포넌트는 AI가 쏟아내는 코드의 전형적인 모양입니다. 기능마다 상태와 useEffect를 하나씩 추가해서, 동작은 하지만 상태끼리의 관계를 아무도 모르게 됩니다.
- useEffect가 늘어나는 이유의 대부분은 "파생값을 상태로 들고 있어서"입니다. 계산하면 사라질 상태를 동기화하느라 effect가 생깁니다.
- 상태를 서버 상태 / 클라이언트 상태 / 파생값으로 구분하는 감각이 이후 단계(관심사 분리, 흐름 소유권)의 기반이 됩니다.

## 실습 대상

`src/components/TodoListBad.tsx` (약 310줄). 앱의 "2단계 Todo 리팩토링" 탭에서 동작을 확인할 수 있습니다.

## 어떻게 진행하나

### 파생값부터 의심한다

`stats`는 `todos`에서 계산할 수 있는 값인데 상태로 선언되어 있고, effect가 동기화하고 있습니다. 상태와 effect를 지우고 계산으로 바꾸면 코드가 줄면서 동기화 시점 버그도 함께 사라집니다.

### effect마다 심문한다

남은 useEffect 하나하나에 "외부 시스템과의 동기화인가"를 묻습니다.

- localStorage 저장/복원 — 외부 시스템입니다. 다만 지금 구현이 최선인지(가짜 로딩 `setTimeout`, 전역 변수 `lastSavedTodos`)는 별개 문제입니다.
- input 테두리 색을 바꾸는 effect — DOM 스타일은 React가 그리는 대상이지 동기화할 외부 시스템이 아닙니다. 렌더링으로 표현하세요.

### 사용자 피드백을 상태로

`alert`·`confirm`과 핸들러 안에서 `style`을 직접 만지는 코드(배경색 + `setTimeout` 복원)는 "피드백 UI"라는 관심사가 명령형으로 흩어진 것입니다. 상태로 표현하고 렌더링이 그리게 하세요.

### 숨은 버그

아래 증상을 직접 재현해보세요.

1. 필터가 "전체"일 때 할일을 추가하면 목록 순서가 이상하게 바뀌는 경우가 있습니다. `getFilteredTodos`의 `sort`가 무엇을 정렬하고 있는지 확인해보세요.
2. 할일을 추가해도 화면이 즉시 갱신되지 않는 경우가 있습니다. 1단계에서 본 유형입니다.
3. 새로고침하면 마지막 1초 사이의 변경이 사라지거나, 저장 effect와 복원 effect가 서로를 덮어쓰는 순서 문제가 없는지 살펴보세요.

잡은 버그는 원인을 한 문장으로 설명할 수 있어야 하고, 고치지 않은 것은 원인 추정과 제외 이유를 남깁니다.

## 셀프 리뷰

1. 상태 목록을 보고 서버 상태 / 클라이언트 상태 / 파생값을 구분할 수 있는가
2. 파생값이 `useState`로 남아 있지 않은가
3. 남은 useEffect마다 "무엇과의 동기화인지" 답할 수 있는가
4. 전역 변수가 0개인가
5. 렌더링이 그릴 수 있는 것을 핸들러나 effect가 DOM으로 직접 그리고 있지 않은가
